## 1. AI-маркетолог {#1-ai-маркетолог}

**Slug:** `client-segmentation` | **Тип:** Маркетинг  
**KEYWORDS:** Google Apps Script, Google Sheets, WAHelp API, LTV, send_date, idFirst  
**Технологии:** Google Apps Script, Google Sheets, WAHelp API

### Workflow (6 этапов):
1.  **Инициализация:** Загрузка листов «Клиенты», «Шаблоны», «Акции», «Персонализация» в RAM
2.  **Глобальная сегментация:** Определение типа (Visitor/Lead/Buyer), лояльности (1/2-4/5+), активности (Актив/Пассив/Потерян)
3.  **Расчет даты:** `send_date` на основе `minInterval` (для постоянных) или `avgInterval` (для разовых)
4.  **Подбор контента:** Поиск уникального промо (Персонализация) → групповое (Акции) + сборка шаблона
5.  **Отправка:** Формирование сообщения и вызов WAHelp API
6.  **Логирование:** Запись результата на лист «Логи»

### Типы клиентов:
*   **Visitor:** Есть хотя бы один визит "пришел"
*   **Buyer:** Совершил покупку, но еще не был на визите
*   **Lead:** Записался, но не пришел
*   **Permanent:** 2+ визита за последние 90 дней (ядро активной аудитории)
*   **Former Permanent:** Были 2+ визита в прошлом, сейчас 0 за 90 дней (целевой сегмент для реактивации)

### Типы потребления:
*   **massazhnik:** 80%+ услуг категории "Массаж"
*   **spashnik:** 80%+ услуг категории "СПА"
*   **universal:** Нет доминирующей категории (< 80%)

### Принцип idFirst (код-пример):
```javascript
// ❌ Медленно и ненадежно
if (client.activity === "Активный") { ... }

// ✅ Быстро и надежно
if (client.activityId === 1) { ... }
```

### Формула send_date:
*   **Для абонементов:** `Дата визита + 30 дней`
*   **Для визитов:** `Дата визита + (minInterval - 3) дней`

## 2. AI-генератор UI {#2-ai-генератор-ui}

**Slug:** `interface-generator` | **Тип:** Разработка  
**KEYWORDS:** prompt.md, v2.ini, System Codes, AST, роутер промптов  
**Технологии:** LLM, Prompt Engineering, AST

### Workflow (5 этапов):
1.  **Запрос пользователя:** Текст или JSON
2.  **Роутер:** Определяет режим (JSON → CSS → HTML+JS по приоритету)
3.  **Движки генерации:** CSS / HTML+JS / Парсер кодов
4.  **Пост-обработка:** Удаление "болтовни", очистка путей, нормализация
5.  **Готовый код:** CSS / HTML+JS / JSON

### Режимы работы:

#### Режим 1: CSS-only
*   **Промпт:** `cssOnlyHandler`
*   **Логика:** Анализ селектора → Определение свойств → Генерация CSS
*   **Ограничение:** Не изменяет HTML-структуру

#### Режим 2: HTML + JS
*   **Промпт:** `generateHTMLJS`
*   **Логика:** Анализ описания → Генерация HTML → Добавление vanilla JS
*   **Ограничение:** Только клиентская логика (серверная помечается `// TODO`)

#### Режим 3: System Codes (JSON)
*   **Промпт:** `system_code_parser`
*   **Логика:** Получение JSON → Поиск в базе → Возврат JSON
*   **Ограничение:** Максимум 3 кода в ответе

### Корпус контекста (модули V01-V08):
**Формат:** `Module|Template|$CODE$|Description;;`

### Архитектурные принципы:
*   **Stateless:** Каждый запрос независим
*   **Фокус на клиентской части:** Нет серверной логики
*   **Детерминированный роутинг:** Четкие правила выбора режима

## 3. GPT-ассистент с RAG {#3-gpt-ассистент-с-rag}

**Slug:** `gpt-assistant` | **Тип:** Техподдержка  
**KEYWORDS:** Omnidesk, Gemini 2.5 Pro, RAG-разметка, gpttunnel, Confident Score  
**Технологии:** Google Apps Script, Gemini 2.5 Pro, Omnidesk API, Vector DB

### Жизненный цикл тикета:
1.  **Вход:** Omnidesk (Raw HTML) → Очистка текста
2.  **RAG-поиск:** Векторизация → Поиск по RAG-файлу → Анализ кандидатов
3.  **Генерация:** Сборка контекстного пакета → Вызов LLM
4.  **Выход:** Расчет `Confident Score`
    *   Score ≥ 80% → Ответ в Google Sheet как **«Подсказка оператору»**
    *   Score < 80% → Сохранение только **JSON-лога** (для отладки)

### Эволюция моделей:
1.  **Ранняя (Каскад):** Gemini Flash (L1: поиск) → GPT-4o (L2: уточнение) → GPT-4 mini (L3: стиль)
    *   **Недостаток:** С ростом RAG-базы L2 стал избыточным, последовательные вызовы замедляли процесс
2.  **Текущая:** Одна модель **Gemini 2.5 Pro** (выполняет цепочку рассуждений автономно)
    *   **Преимущества:** Быстрее, точнее, предсказуемее (вся цепочка в логах)

### Модули Apps Script:
*   `01_ErrorHandler.js` — Централизованная обработка ошибок
*   `02_Utils.js` — Работа с текстом, датами, данными
*   `03_GptApi.js` — Управление Gemini/GPT
*   `04_Omnidesk.js` — Интеграция с тикет-системой
*   `05_Triggers.js` — Управление триггерами по расписанию
*   `06_History.js` — Хранение истории обращений
*   `07_ReportGenerator.js` — Аналитические отчеты
*   `08_UrlValidator.js` — Проверка ссылок на безопасность
*   `10_AdvancedSpamFilter.js` — Фильтрация спама
*   `12_PlaygroundTester.js` — Тестирование промптов
*   `CONFIG.js` — Параметры системы и API-ключи

### Структура RAG-файла:
```
<BEGIN_BLOCK>
<Q> Как восстановить пароль?
<A> Чтобы восстановить доступ, перейдите по ссылке...
<CATEGORY> Авторизация
<SUBCATEGORY> Восстановление пароля
<KEYWORDS> пароль; доступ; сброс;
<END_BLOCK>
```

### Структура JSON-лога:
```json
{
  "question": "как восстановить пароль?",
  "retrieved_candidates": [
    {"id": 23, "category": "Авторизация", "similarity": 0.91},
    {"id": 57, "category": "Аккаунт", "similarity": 0.77}
  ],
  "selected": {"id": 23, "reason": "наибольшее совпадение"},
  "model_score": 86,
  "final_response": "Чтобы восстановить пароль, нажмите..."
}
```

## 4. AI-тестировщик чат-ботов {#4-ai-тестировщик-чат-ботов}

**Slug:** `bot-autotest` | **Тип:** QA/Тестирование  
**KEYWORDS:** Playwright, Selenium, Gherkin, LLM-метрики, Semantic Validation  
**Технологии:** Playwright, Selenium, LLM, REST API

### Workflow (5 этапов):
1.  **Загрузка файла:** Справочный файл (promo.json) как "источник правды"
2.  **Анализ и генерация тест-кейсов:** LLM анализирует файл и формирует тест-кейсы
3.  **Выполнение сценариев:** Через API или эмуляцию UI (Playwright/Selenium)
4.  **Сверка результатов:** Ответы сверяются с правилами акции
5.  **Формирование отчета:** LLM формирует финальный отчет

### Типы ботов:

#### NLU-боты (жесткие сценарии):
*   Алгоритмические правила и предопределенные интенты
*   Фиксированные сценарии: "вопрос → ожидаемый ответ"
*   Проверка точности скриптовых диалогов

#### LLM-боты (свободная форма):
*   Вариативные ответы на естественном языке
*   Сценарии в свободной форме, проверка соответствия сути
*   Метрики: корректность, полнота, исключения (не дословное совпадение)

### Пример диалога (тест акции "1+1=3"):
```
CLIENT: Здравствуйте! Вчера я совершила покупку по акции «1+1=3», 
но бесплатный товар мне не был предоставлен.

BOT: Акция «1+1=3» работает так: при покупке трёх товаров один 
из них с наименьшей ценой предоставляется бесплатно.
```

## 5. Пайплайн безопасности email {#5-пайплайн-безопасности-email}

**Slug:** `email-safety-pipeline` | **Тип:** Безопасность  
**KEYWORDS:** Node.js, Express, SpamAssassin, Puppeteer, Google Safe Browsing, Docker  
**Технологии:** Node.js, Express, SpamAssassin, Puppeteer, Google Safe Browsing API, Docker

### Технологический стек:
*   **Node.js + Express:** API-эндпоинт для приема HTML-шаблонов
*   **SpamAssassin API:** Анализ спам-триггеров
*   **Puppeteer:** Скриншоты HTML в headless Chrome (десктоп/мобайл)
*   **Google Safe Browsing API:** Проверка URL на фишинг и вредоносное ПО
*   **Docker:** Контейнеризация всей системы

### Workflow (3 этапа):
1.  **Анализ репутации (Reputation):** SPF/DKIM/DMARC, черные списки (Spamhaus) → Вердикт: Red/Yellow/Green
2.  **Анализ контента (Content):** Спам-триггеры, фишинговые паттерны, проверка URL
3.  **Финальное решение (Final Verdict):** Агрегация результатов → GO/STOP + JSON-отчет

### Детальные анализаторы:

#### Reputation:
*   **Аутентификация отправителя:** SPF, DKIM, DMARC
*   **Репутация домена и IP:** Проверка по Spamhaus

#### Content:
*   **Спам-триггеры:** Поиск слов ("бесплатно", "гарантированный доход", "только сегодня")
*   **Безопасность ссылок:** Проверка через Google Safe Browsing API
*   **Техники маскировки:** Скрытый текст, нерелевантные анкоры

### Пример отчета:
```json
{
  "final_verdict": "STOP",
  "reputation_check": {
    "status": "green",
    "details": "SPF, DKIM, DMARC valid. Not in blacklists."
  },
  "content_check": {
    "status": "red",
    "flags": [
      {"risk": "yellow", "comment": "Слова срочности ('только сегодня')"},
      {"risk": "red", "comment": "Нереалистичные обещания ('гарантированный доход')"},
      {"risk": "red", "comment": "Агрессивный призыв к действию"}
    ]
  }
}
```

## 6. Scenario Nexus / Victory {#6-scenario-nexus--victory}

**Slug:** `scenario-nexus` | **Тип:** AI-архитектура  
**KEYWORDS:** JSON-Schema, Sentinel QA, Nexus CRM, Logic Engine, Детерминизм  
**Технологии:** JSON-Schema, CRM, LLM, Validation Engine

### 7-уровневая архитектура:

1.  **Декомпозиция сценария (HTML):** Разбор скриптов на атомарные вопросы и условия
2.  **Schema Mapping (JSON Schema):** Конвертация логики в строгий граф состояний
3.  **Nexus CRM (слой управления):** Изменения в CRM автоматически пересобирают логику AI-агентов
4.  **Динамическое исполнение (Runtime):** AI-агенты получают текущее состояние JSON Schema (не текстовый промпт)
5.  **Сбор метрик:** Каждый переход логируется в CRM (точная воронка)
6.  **Sentinel QA (валидация галлюцинаций):** Проверка соответствия JSON-чертежу
7.  **Бизнес-аналитика (BI):** Выгрузка данных для анализа эффективности

### Sentinel QA (3 функции):
*   **Compliance:** Проверка на юридические и бизнес-регламенты
*   **Logic Guard:** Блокировка действий вне активного JSON-узла
*   **Hallucination Trap:** Выявление выдуманных фактов через кросс-чекинг с CRM

### Бизнес-результаты:
*   **Масштабируемость:** Один сценарий → сотни ботов без потери качества
*   **Agility:** Правки в CRM внедряются мгновенно без релиза кода
*   **Reliability:** 99% блокировка галлюцинаций через схемы
*   **Visibility:** Прозрачность каждого шага AI для аналитики

### Проблема vs Решение:
*   **Проблема (Хаос):** Объемные промпты → AI путает шаги, забывает вопросы, дает неверные обещания
*   **Решение (Детерминизм):** Набор микро-инструкций, привязанных к JSON-узлу → AI видит только текущий шаг

## 📚 Глоссарий (Glossary) {#глоссарий-glossary}

**Терминов:** 11 | **Категории:** Технические, Бизнес-метрики, AI/ML

*   **idFirst:** Числовые ID категорий (производительность, надежность)
*   **send_date:** Автоматически вычисленная дата рассылки
*   **minInterval:** Самый короткий промежуток между визитами клиента
*   **avgInterval:** Среднестатистический промежуток для сегмента
*   **massazhnik / spashnik:** Сегмент с долей профиля > 80%
*   **universal:** Клиент без доминирующей категории
*   **Confident Score:** Оценка уверенности модели (0-100)
*   **Sentinel QA:** Блокировщик галлюцинаций через JSON-Schema
*   **System Code:** Токен `$CODE$` для динамической подстановки
*   **RAG:** Retrieval-Augmented Generation (поиск + генерация)
*   **AST:** Abstract Syntax Tree (дерево структуры кода)
